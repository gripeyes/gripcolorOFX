# Nuke artist evaluation

All eight native effects are exposed through the **Rendition** node category and main menu. Scene, Tone, Volume, Density, Crossover, Crosstalk, Strip and Inspector have exact identity defaults after explicit source interpretation, Artist controls, collapsed Expert controls and semantic tooltips. Main-menu Quick Help explains input interpretation and candidate status. Auto resolves the project OCIO scene_linear role through the installed Nuke startup integration. Unsupported roles require manual interpretation; Auto does not guess a gamut.

Open `build/artist-tests/Rendition-artist-bench.nk`. It uses the user's local `config-2020.ocio`, **sRGB / Flawed Emulsion 2**, and explicitly interpreted Linear Rec.2020 EXRs. Source Switch chooses structured/CG or six approved sample frames; Target Switch chooses six editable recipes. Viewer inputs compare candidate and source. Native default nodes, reconstruction viewers and candidate/baseline viewers are in the same graph. Existing DRT is applied only by Viewer/preview, never inside the OFX.

The original ACES files are AP0/D60, verified using both container flag and chromaticities. `artist/sample_frames.py` converts through the user's OCIO configuration into Rec.2020/D65. Every third pixel is sampled for manageable fixtures; no final-resolution or filtered quality claim is made. Alpha and signed/HDR scene values are retained. PNG previews alone clip after the selected display transform. See `approved-assets.json` for source hashes and interpretation. Dataset license/embedded credits accompany the package. The user's DRT/config is an external prerequisite, not redistributed.

1. Inspect the source, candidate and fitted baseline with one fixed view. Try both display-sized and close-up views. Judge black hue identity, skin coherence, palette hierarchy, accent survival, contamination and colour death.
2. Change a small number of artist controls. Record actual elapsed human time and changed controls. Solver/render times in reports are not human interaction times.
3. Reuse the unchanged recipe on another photographic/CG source, then exposure-sweep Scene before the recipe. Inspect seams, clipping-like appearance, neutral drift and signed/alpha edges. Test full-resolution originals separately before production acceptance.
4. Review the five reference challenge panels. References are independent approved sample frames under the same DRT. Fits use existing creative parameters, palette quantiles/covariance and no extra LUT/stock/masks. Differences in lighting, content and palette make a low descriptor error insufficient evidence of look reconstruction.
5. Compare Density with exposure+saturation, Strip with a matrix+curves, Volume with hue curves, and Crossover with smooth luminance keys. Frozen baseline EXRs are diagnostics; baseline equations and fitted parameters are available in `artist/simplicity.py` and `baseline-models.json`. Record preferred behavior and why, including ease/speed, continuity and coherence. Multiple starts, wider stimuli and artist-tuned baselines may overturn the initial fits.
6. Fill `feedback-template.json`; record the image, parameters, source exposure, observation and expected result for every repeatable deficiency. Reference challenge and simplicity scores remain unaccepted until this evidence exists.

Density and Strip remain **research candidates**. They pass only when useful behavior or better control/continuity/coherence/interaction is demonstrated against the simpler baselines. Numerical non-equivalence is not superiority. Failures should lead to targeted fixes or simpler models, not broad literature expansion. The user accepts basic usability of the eight current nodes. The 0.2 Inspector Lab adds Jacobian, structure, HK, palette and aggressive baseline diagnostics; its stronger superiority/reconstruction judgements remain open. See [0.2 phase](DEEP_VALIDATION_0_2.md).

The artist build is a local ad-hoc-signed arm64 CPU candidate, not a production release. Flame smoke testing and OFX host Metal parity are separate pending gates.

To relocate the package, edit `artist/targets.json` to point to the existing user OCIO config and run Nuke `-t tools/nuke_artist_bench.py` from the extracted package to regenerate absolute Read paths. Offline artist tools require the repository build/Python environment; OFX usage does not. The initial saved graph uses this workstation’s fixture paths.
